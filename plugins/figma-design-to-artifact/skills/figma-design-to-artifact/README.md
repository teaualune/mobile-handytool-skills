# figma-design-to-artifact

A [Claude Code](https://claude.com/claude-code) **skill** that turns Figma design
nodes into technical-requirement artifacts. For every valid Figma node URL it
produces, side by side:

1. **Sample code** — generated by the "Figma to Code" Figma plugin and saved as a
   *labeled reference file* (a spec artifact — explicitly **not** production
   source to drop into your app).
2. **A 2x PNG screenshot** — exported from Figma's own image exporter.

**No Dev Mode?** (free Starter plan, View/Collab seat, view-only file) Plugins
can't run there, so the skill checks which signed-in Figma account to use, and
then produces the **tree output** instead:

1. **`<slug>.css`** — Figma's built-in *Copy as code → CSS (all layers)*.
2. **`<slug>.layers.json`** — the node's full layer tree with every sublayer's
   Properties-panel values.
3. **`icons/`** — the node's vector icons and graphics (logos, background
   shapes) as SVG files.
4. **The 2x PNG**, as above.

You can also ask for the tree output, or both outputs, when you do have Dev
Mode. In a blind test on one screen, both outputs led a coding agent to an
equally faithful Flutter implementation. The tree output takes longer to
produce (~25 s more per node) and is ~1.8× larger, but it doesn't depend on the
plugin, works for any target stack, and keeps variable, style and component
names.

The whole workflow is browser-driven: Claude drives a real Chrome session through
the actual figma.com UI, runs the plugin (or reads the panels), extracts the
output, and exports the image. Nothing goes through the Figma MCP, Dev Mode API,
or REST API — the point is to capture exactly what Figma's own UI produces, and
free seats get only a handful of REST calls a month.

## ⚠️ Hard dependencies

This skill is glue around three moving parts it does **not** control. If any of
them is unavailable or changes, the skill degrades or stops — read this before
relying on it.

### 1. Claude-in-Chrome (browser automation)

The skill is **entirely** browser-driven and needs the `mcp__claude-in-chrome__*`
tools (`navigate`, `find`, `read_page`, `get_page_text`, `computer`,
`javascript_tool`, `tabs_*`). Without them there is no fallback — the workflow
stops at its Step 2 gate. You must have the Claude-in-Chrome extension installed,
connected, and granted site permissions for figma.com.

### 2. figma.com's web UI

Every step navigates and clicks through the live figma.com editor: Dev Mode URLs
(`?node-id=<id>&m=dev`), the right-panel **Plugins** tab, **Recents**, the
Design-mode **Export** section, and — without Dev Mode — the canvas context
menu, the **Layers** panel and the **Properties** panel (read through their
DOM). This UI is not a stable API — **if Figma restructures these panels, the
navigation steps in [`figma-browser-navigation.md`](./figma-browser-navigation.md)
will need updating.** That reference file documents the current, load-bearing
UI quirks (view-only mode, the background-tab "Loading…" hang and its visibility
spoof, how Dev Mode can't export a PNG file, the `/`-in-frame-name ZIP trap,
Chrome's repeated-download block, the Layers panel's DOM, etc.).

You must be **logged in to Figma yourself** — the skill never types credentials.
It asks you to sign in in the browser and continues once you confirm. If the
account has no Dev Mode on the file and you're signed in to several accounts, it
stops and asks whether you want to switch to one that has Dev Mode; you do the
switching.

### 3. The "Figma to Code" Figma plugin

Code generation comes entirely from this community plugin:

> **Figma to Code (HTML, Tailwind, Flutter, SwiftUI)** by Bernardo Ferrari
> <https://www.figma.com/community/plugin/842128343887142055>

The skill runs it from the editor's **Recents** and reads back its output. If the
plugin isn't in your Recents/Community, is renamed, changes its output format, or
errors, code generation for that node fails — the skill then offers to try another
plugin you name, or to skip code for that node (the PNG export still runs). Its
four output languages (HTML, Tailwind, Flutter, SwiftUI) are exactly the targets
this skill maps a repo onto. Plugins need Dev Mode or edit access; on a
view-only file without Dev Mode the skill uses the tree output (CSS + layer tree)
instead.

## What you get

For each node, in `<artifact_location>/<slug>/`:

```
<slug><ext>          # plugin output: generated design-reference code (.dart | .swift | .html)
<slug>.css           # tree output: Figma's CSS for all layers
<slug>.layers.json   # tree output: the layer tree
icons/<name>.svg     # tree output: vector icons and graphics
<slug>@2x.png        # always: 2x PNG screenshot of the node
```

Plus a top-level `manifest.md` with the output, access tier and account used,
and every node's source URL, chosen language, filenames, and per-node status.

The code and CSS files carry a `GENERATED DESIGN REFERENCE — NOT PRODUCTION CODE`
header so they are never mistaken for app source.

### The layer tree format

There is no standard "design layer tree" format besides Figma's own REST node
schema, so `<slug>.layers.json` borrows that schema's keys for structure — `id`,
`name`, `type`, `characters`, `children`, in REST child order, with instance
sublayers as `I<instance>;<layer>` ids — so tools and agents that know Figma's
API read it directly. The values come from Figma's Properties panel as a viewer
sees them (`"Width": "Fill (375px)"`, variable and style names, hex colors), kept
under `properties` rather than forced into REST fields the panel doesn't show
(absolute positions, RGBA floats):

```json
{"id": "I120:3456;78:910", "name": "Time", "type": "TEXT", "characters": "9:30",
 "properties": {"Parent component": "Status bar",
   "Layout": {"Width": "29px", "Height": "20px"},
   "Typography": {"Font": "Roboto", "Weight": "500", "Size": "14px", "Line height": "20px"},
   "Colors": ["M3/sys/light/on-surface", "#1D1B20"]}}
```

## How it works

1. **Collect requirements** — validate the Figma URLs, pick an artifact folder
   (default `./figma-artifacts`), detect the repo's tech stack, and choose the
   output (`auto`, `tree` or `both`). The skill **stops and reports** the valid
   targets and every excluded URL before touching the browser.
2. **Open Figma, authenticate, check access** — gate on the Claude-in-Chrome
   tools, navigate to the first target, ask you to log in if needed, then work
   out whether the account has Dev Mode, edit access, or view access. Plugin
   output wanted, no Dev Mode, and several signed-in accounts → it stops and
   asks whether to switch.
3. **Code** — plugin output: run "Figma to Code" via Dev Mode → Plugins →
   Recents and save its output as a labeled reference file. Tree output: save
   Figma's *CSS (all layers)*, scan the Layers + Properties panels into
   `<slug>.layers.json` (roughly 10 layers per second), and copy the vector
   icons and graphics out as SVG.
4. **Export a 2x PNG** — via Design mode → Export at 2x/PNG, placed beside the
   code.

The full step-by-step contract lives in [`SKILL.md`](./SKILL.md).

## Files in this skill

| File | Purpose |
| --- | --- |
| [`SKILL.md`](./SKILL.md) | The skill definition and step-by-step workflow contract. |
| [`figma-browser-navigation.md`](./figma-browser-navigation.md) | Detailed figma.com UI navigation, the access/account check, the tree output, gotchas, and troubleshooting. **Read before Step 2.** |
| [`validate_figma_urls.py`](./validate_figma_urls.py) | Classify URLs as valid node targets vs. excluded; emit file key, node id, and a `slug`. |
| [`detect_tech_stack.py`](./detect_tech_stack.py) | Map a repo to one plugin language (`flutter` \| `swiftui` \| `tailwind` \| `html`, HTML fallback) with evidence. |
| [`build_layer_tree.py`](./build_layer_tree.py) | Turn the in-page layer scan's download into the `<slug>.layers.json` tree, with completeness warnings. |
| [`icons.py`](./icons.py) | List the vector layers worth exporting from a layer tree, and write the downloaded SVG bundle out as files. |

### Helper usage

```bash
# Validate one or more Figma node URLs
python validate_figma_urls.py "https://www.figma.com/design/<key>/<name>?node-id=1-2"

# Detect the tech stack of a repo (defaults to the current directory)
python detect_tech_stack.py [REPO_DIR]

# Build a layer tree from a layer-scan capture (--pretty to indent it for humans)
python build_layer_tree.py ~/Downloads/figlayers_<slug>.json --source-url "<node URL>" > <slug>.layers.json

# List the vector layers to export, then save the downloaded SVG bundle
python icons.py list <slug>.layers.json
python icons.py save ~/Downloads/figicons_<slug>.json <slug>/icons
```

All of them print JSON to stdout and a human-readable summary (or warnings) to
stderr.

## Requirements

- **Claude Code** with the **Claude-in-Chrome** browser tools connected.
- A Chrome session where you can **log in to figma.com** with access to the target
  files. Dev Mode is optional — without it you get the tree output (CSS + layer tree).
- The **"Figma to Code"** plugin available in that Figma account (Dev Mode path).
- **Python 3** (standard library only) to run the helper scripts.
- A writable local filesystem — every artifact lands in `~/Downloads` as a
  browser download first, then gets moved into the artifact folder. Chrome may
  ask you to allow multiple downloads from figma.com once.

## Notes & safety

- **No credentials, ever.** You log in, and switch accounts, yourself; the skill
  never types an email or password.
- **No Figma MCP / Dev Mode API / REST API.** Even if connected, the MCP produces
  different artifacts and would defeat the skill's purpose, and free seats get
  only a handful of REST calls a month — everything goes through the browser.
- **No permission workarounds.** The skill never clicks *Request access*,
  *Upgrade* or *Ask to edit* on its own, and never patches Figma's permission
  checks.
- **Downloads land in `~/Downloads` first.** The skill confirms before the first
  download, then moves files into the artifact folder. If the browser runs on
  another machine, it will tell you the filename and ask you to move it
  (`png: manual-move-needed`).
